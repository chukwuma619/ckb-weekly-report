# Weekly report — 8 June 2026 to 14 June 2026

**Project:** `fiber-peer-pay` — monorepo for website integrators building Fiber checkout without running `fnn`.

Github: https://github.com/chukwuma619/fiber-peer-pay

## Summary

**Production-ready node package foundations** — validation layer, payment confirmation, merchant pairing, and idempotent invoice submission. Added **framework adapters** for vanilla HTTP (`web`), Express, and Next.js App Router so integrators can mount the same routes everywhere.

**Also this week:** Vitest unit tests for the full order lifecycle, comprehensive `packages/node/README.md`, and README/roadmap updates clarifying that `@fiber-peer-pay/node` is the primary focus.

## What I shipped (high level)

1. **Validation & error handling** — `validateCreateOrderInput`, `validateSubmitInvoicePayload`, `validateMarkPaidInput`; exported `HttpError` from handlers; CKB amount and invoice field checks (`5b6552c`, 2026-06-09).

2. **Payment confirmation & merchant pairing** — `handleMarkPaid` for marking orders paid; `createMerchantCredentials()` and `createMerchantRegistry()` for seller API tokens; idempotent `submitInvoice` to tolerate agent retries (`5b6552c`, 2026-06-09).

3. **Framework adapters** — `createWebHandlers` (`@fiber-peer-pay/node/web`) for Request/Response runtimes; `createExpressRouter` for Express 4+; `createNextHandlers` for Next.js App Router; default path constants aligned with Fiber Desktop (`5b6552c`, `9527f2a`, 2026-06-09).

4. **Tests & docs** — Vitest config and unit tests for order lifecycle, Express routes, and web handlers; 240+ line package README with vanilla HTML/fetch, jQuery, Express, and Next.js examples; updated root README and ROADMAP to reflect Phase 0 completion (`5b6552c`, `9527f2a`, 2026-06-09).

5. **Housekeeping** — Removed deprecated Next.js helpers in favour of the unified web handler surface; refreshed `package-lock.json` with Express/Next.js type deps (`9527f2a`, 2026-06-09).
